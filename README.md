# Система контролю відпусток працівників

## Опис

Система для створення запитів на відпустки та лікарняні працівниками, а також затвердження їх адміністраторами.
Система контролює максимальні залишки вихідних та лікарняних за обраною схемою (накопичення днів кожного місяця, або отримання доступу до всіх вихідних на початку року). Налаштувати схему може адміністратор, який створив робочу область (наприклад керівник компанії). Ця схема застосовується глобально для всіх працівників. Виключенням є лікарняні, які є доступні в повному обсязі з початку року.

Така система дозволяє зручно керувати залишками своїх вихідних, робити запити на відпустки в декілька кліків та забезпечує просте їх схвалення.

Для працівників зручність полягає у зменшені бюрократії та часу очікування на затвердження відпустки. Також зручність полягає у візуальному спостереженні за своїми залишками, а також календарний вигляд з затвердженими відпустками.

## Задача

- Управління відпустками працівників компанії
- Перегляд залишків вихідних та лікарняних
- Створення/схвалення відпустки

## Предметна область

*Управління ресурсами підприємства*

## Користувачі

- Керівники компаній/команд
- Фахівці з управління ресурсами компанії/команди
- Працівники компанії/команди

## Вимоги

**Функціональні вимоги**

1. Користувач може створити та управляти своїм акаунтом
2. Користувач може запрошувати інших користувачів до команди
3. Користувач може бачити дані про залишки вихідних днів та лікарняних
4. Користувач може створити запит на отримання відпустки
5. Адміністратор команди може схвалити запит на відпустку
6. Адміністратор може переглядати календар з візуалізацією відпусток своїх працівників

**Нефункціональні вимоги**

1. Система захищає дані користувачів (хешування паролів, авторизація з використанням JWT-токенів)
2. Система реалізує рольову модель доступу до даних (адміністратор/працівник)
3. Кодова база системи покрита тестами
4. Система є відмовостійкою через валідацію даних введених користувачами
5. Система дозволяє створити/схвалити запит на відпустку швидко і без допомоги завдяки інтуїтивному інтерфейсу

## Ролі

**Адміністратор** - будь-хто з адміністрації компанії:
- Керівник (CEO)
- Менеджер конкретного праціника
- Фахівець з управління людськими ресурсами (HR)
  
Адміністратор має можливість затверджувати відпустки, переглядати календарі з усіма відображеними відпустками для підопічних працівників.

CEO та HR можуть додавати інших працівників, призначати для них менеджера, призначати менеджерів
CEO, як найвищий рівень адміністрації може затверджувати відпустку для HR та для себе.

Менеджер працівника може переглядати та затверджувати відпустку лише своїм підопічним. Менеджер може мати багато підопічних, але працівник не може мати більше одного менеджера.

Таким чином, можна побудувати таку схему:

CEO => HR => Менеджер => Працівник,

де користувач ліворуч може переглядати та затверджувати відпустки користувачів праворуч

**Працівник** - працівник компанії незалежно від позиції. Приклади працівників:
- Розробник
- Бухгалтер
- Дизайнер

## User Stories

### 1

Як новий користувач системи, я хочу створити акаунт у системі, щоб керувати своїми відпустками.

Acceptance Criteria: Новий користувач вводить дані для реєстрації (електронна пошта, ім'я, прізвище, стать, пароль) та натискає на кнопку "Створити акаунт". Система перевіряє дані та створює акаунт, якщо все вірно, а тоді переадресовує користувача на сторінку авторизації для подальшого входу в акаунт з допомогою пароля.

### 2

Як працівник команди, я хочу створити запит на відпустку в системі, щоб адміністратор команди зміг його переглянути та затвердити.

Acceptance Criteria: Працівник обирає дату початку та кінця відпустки, заповнює опис та натискає кнопку "Створити запит" => Система зберігає запит на відпустку, якщо працівник не перевищив кількість доступних йому днів.

### 3

Як адміністратор команди, я хочу переглянути та затвердити запит на відпустку від працівника, щоб переконатись, що запит вірний та працівник має можливість піти у відпустку.

Acceptance Criteria: Адміністратор бачить у списку запитів конкретний запит, обирає його, аналізує та натискає кнопку "Затвердити" => Система зберігає оновлений статус запиту та оновлює календарний вигляд, щоб показати конкретні дні відсутності працівника.
